## What now works

| Requested step | Current implementation | Verified boundary |
|---|---|---|
| 1. Upload reports | PDF/text extraction, installed Windows OCR for images/scans, up to five reports, editable transcription and required review | Genuine extraction verified in the earlier checkpoint; current clinical fields use the same extraction path. OCR can misread symbols and layouts. |
| 2. Extract medical facts | Numeric results/units/ranges/dates plus explicit diagnoses and medications; source page/line/quote; negation, uncertainty, historical/family mentions; literal dose text; unknown labelled entries flagged | Bounded English vocabulary/labelled-section rules, not comprehensive clinical NER. Diagnoses are documented assertions rather than independently established conditions. |
| 3. Patient health history | Unified chronological laboratory/diagnosis/medication timeline, undated entries, duplicate-source retention and conflicting-assertion warnings | Document dates do not establish disease onset or medicine start/current adherence. No automatic choice of a conflicting assertion. |
| 4. Patterns/simulation | Dated report comparisons; measured user CGM → audited daily aggregation → live new VAE/GRU inference → correlated residual simulation, charts, cited note and downloads. Past-30-day mean comparator shown. A report alone supplies no CGM history. New models have internal evaluation only; no individualized clinical risk is estimated. |
| 5. Evidence retrieval | 16 versioned NLM/NIDDK educational/guideline passages, bounded ADA 2026 recommendation excerpt with locator; hybrid BM25/word/character vectors and optional offline BGE semantic embeddings | Limited corpus, not every specialty or an exhaustive guideline library. Similar-patient retrieval remains an additional unimplemented capability. |
| 6. Cited explanation | Four-section local summary and explicit optional structured LLM composition: findings, attention, uncertainties and doctor questions, with evidence links. Same-patient confirmed CGM simulation aggregates can join the reviewed report explanation with distinct S1 provenance. | The LLM orders complete approved claims; it cannot invent free medical prose. Changed claims invalidate old summary plans. Live account/API execution was not tested. No paid request occurred. |

The six workflow paths are implemented **within these input and research boundaries**. This is not a claim of perfect extraction, clinically reliable prediction, zero hallucination, or a fully validated public healthcare deployment.

## Model/algorithm choices

- Retrieval uses a small-corpus hybrid of BM25 and normalized word/character TF-IDF, with explicit applicability filtering. The optional learned semantic encoder is locally cached `BAAI/bge-base-en-v1.5`, pinned to revision `a5beb1e3e68b9ab74eb54cfd186867f64f240e1a`, CPU, safe tensors, local files only, remote code disabled. No installation/download was performed. [Publisher model card](https://huggingface.co/BAAI/bge-base-en-v1.5).
- Optional structured composition defaults to GPT-6 Astra, with GPT-6.1 Sol and pinned GPT-4.1 selectable. This is a documented capability/quality choice, not a measured healthcare superiority claim. Independent server validation remains required despite strict provider schemas. Reasoning-model requests omit unsupported temperature settings, set a bounded output budget, use a 45-second timeout/no automatic retries, and request `store=False`. [Official model guidance](https://developers.openai.com/api/docs/guides/latest-model), [Structured output documentation](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=chat).
- Clinical assertions use conservative local rules with explicit labels, context/negation boundaries and reviewed unknown entries. A pretrained clinical extractor was not installed or claimed validated. A larger neural extractor would require appropriate consented evaluation data and error measurement before replacing these rules.
- After the user's explicit isolated-retraining approval, a **new CGM-only VAE/GRU release** was trained from fresh raw aggregates using patient-disjoint groups and train-only normalization. Three statistical baselines were compared. The neural model narrowly won validation but did not beat the 30-day mean on test glucose MAE. Correlated residual generation and marginal split-conformal calibration are separate from clinical validation. [CGM model card](../models/CGM_MODEL_CARD.md) provides results; the legacy multimodal VAE/cGAN/GRU weights remain unchanged and experimental.

## Limitations that prevent a stronger readiness claim

1. Extraction is bounded and requires review. Unknown layouts/entities, narrative context, multilingual content, onset/current-medication status and OCR errors remain possible. The earlier real OCR fixture misread `%`; missing units correctly withheld interpretation.
2. CGM history cannot be manufactured from a single report. The corrected default accepts measured CGM with coverage/unit checks; user-confirmed source correctness cannot be independently certified by the software. The optional legacy route still requires the original full multimodal contract, whose lab units/onset flags are unresolved.
3. Legacy preprocessing leakage and calibration defects remain in unchanged original artifacts. The new CGM-only release avoids those specific lab/diagnosis inputs, verifies train-only normalization and independent patient groups, but shows modest test accuracy and incomplete interval coverage. No external clinical validation or causal treatment model exists. Similar-patient retrieval is absent. Sparse reports do not automatically produce future curves.
4. The optional LLM path was verified with mocks and current documentation, not a live paid API. Model/account availability, operational errors, cost and provider data-retention behavior were not measured. No free-form generated medical claims are displayed.
5. Fresh installation, Docker/Linux OCR, multi-user load, memory/cold-start budgets, malicious-document isolation and public security/operations remain unverified. The core Docker image intentionally excludes the optional embedding stack and private research artifacts. Basic shared-token gating is not production patient identity/authorization.
